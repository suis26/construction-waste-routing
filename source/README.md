# 建筑垃圾运输优化算法

源头识别、接收匹配与车辆协同调度。配套《建筑垃圾运输优化算法方案》的参考实现。

## 思路

先在源头确认材料与接收条件, 再联合决定去向、车辆与时间, 避免车开到门口才发现收不了。

算法分四步:

1. 源头识别与分诊: 识别材质标签与置信度, 低置信度或异常订单转人工, 不占运力
2. 接收匹配: 材质须落在设施接收目录内, 类别须允许该类设施, 泥浆强制先进预处理站
3. 联合调度: 选车辆、选去向、排装卸顺序、定到场时刻
4. 集运判据: 分开两趟成本 - 合并一趟成本 - 新增操作成本 > 0 才合并

目标函数: 综合成本 = 行驶 + 等待 + 处置 + 违约

## 运行

    python srs_main.py

输出: srs_result.json, srs_schedule.csv, srs_manifests.csv

## 算例结果

单簇案例, 三个产生点各 4 吨, 12 吨车:

- 分别直送 120 km / 900 元, 首批 08:50 到厂
- 多点集运 50 km / 350 元, 首批 09:30 到厂

扩展场景, 14 个产生点 / 6 个处理设施 / 4 台车:

- 综合成本 3152 -> 2678 元, 降 15.04%
- 总里程 225.1 -> 206.2 km, 降 8.39%
- 趟次 11 -> 8
- 碳排 202.6 -> 185.6 tCO2e, 降 8.39%

成本降幅大于里程降幅, 差额来自趟次减少所省下的出车固定成本。

## 参数来源

成本参数由单簇案例两场景联立反解: 出车固定成本 100 元/趟, 里程单价 5 元/km。
等待 60 元/小时, 违约 200 元/小时, 操作 2 元/吨。

里程单价、等待费率、处置费与碳因子均为算例参数, 落地前须用当地实际台账标定。
